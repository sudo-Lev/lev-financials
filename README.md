# Lev Financials

Локальний дашборд для аналізу банківських виписок без реєстрації, логіна та бекенду.

Користувач імпортує PDF або Excel-виписку, а застосунок локально структурує операції, категорії витрат, регулярні платежі й підписки. Фінансові дані не мають залишати браузер.

## Статус

Завершено фундамент застосунку (кроки 1–6 плану):

- React + TypeScript + Vite;
- перевірки якості, тести та production build;
- дизайн-токени, світла й темна теми;
- source-owned компоненти на базі HextaUI;
- адаптивний application shell і маршрути-заглушки;
- українська як основна мова інтерфейсу.

Наступний крок — узгодити domain model перед реалізацією імпорту та фінансових обчислень. Повний порядок робіт описаний у [плані реалізації](docs/implementation-plan.md).

## Принцип приватності

Lev Financials — local-first застосунок:

- виписки обробляються на пристрої користувача;
- сирі PDF/XLSX-файли, персональні дані та реальні транзакції не комітяться;
- застосунок не відправляє фінансові дані на зовнішні сервіси;
- `.env` використовується лише для конфігурації та секретів інтеграцій, а не як сховище виписок;
- тестові fixtures мають бути синтетичними або надійно знеособленими.

## Технології

- React 19, TypeScript, Vite;
- HextaUI-підхід і Tailwind CSS для UI;
- React Router;
- Chart.js для графіків (на наступних етапах);
- Dexie / IndexedDB для локального зберігання (на наступних етапах);
- PDF.js і SheetJS для локального імпорту (на наступних етапах);
- Vitest і Testing Library;
- Biome для форматування та lint-перевірок.

## Локальний запуск

Потрібні актуальні Node.js LTS і Corepack.

```bash
corepack enable
yarn install
yarn dev
```

Vite покаже локальну адресу застосунку в терміналі.

## Команди

| Команда | Призначення |
| --- | --- |
| `yarn dev` | Запустити development server |
| `yarn build` | Перевірити типи та зібрати production bundle |
| `yarn test` | Запустити тести один раз |
| `yarn test:watch` | Запустити тести у watch-режимі |
| `yarn typecheck` | Перевірити TypeScript без генерації файлів |
| `yarn lint` | Запустити lint-перевірки Biome |
| `yarn format` | Відформатувати підтримувані файли |
| `yarn format:check` | Перевірити форматування |
| `yarn verify` | Запустити всі перевірки, тести та build |

Перед коммітом змін у коді потрібно виконати `yarn verify`.

## Структура

```text
src/
├── app/       # композиція застосунку, providers, router і layouts
├── domain/    # чиста фінансова модель та інваріанти (після узгодження)
├── features/  # завершені користувацькі сценарії
├── pages/     # route-level композиція
├── shared/    # спільні UI-компоненти, i18n та технічні утиліти
└── widgets/   # великі самодостатні частини інтерфейсу
```

Поточні розділи: огляд, транзакції, регулярні платежі, категорії, імпорт і налаштування.

Архітектурні та інженерні правила для coding agents зберігаються в [AGENTS.md](AGENTS.md). `AGENTS.md` є єдиним канонічним джерелом цих правил.

## Розробка

- зміни робимо невеликими самодостатніми коммітами;
- поведінка й тести змінюються в одному комміті;
- зовнішні дані валідуються на межі системи;
- фінансові обчислення не використовують floating-point суми;
- UI використовує дизайн-токени, а не випадкові hardcoded кольори;
- нова залежність повинна мати чітку користь і не порушувати local-first модель.
